# 车记本（iCar）· 车辆记账与保养助手

## 这个 SKILL 能做什么

车记本是一个**纯本地**的车辆记账小程序：加油、充电、保养、维修、日常支出都在用户手机上，不上传服务器。本 SKILL 让用户用一句话完成两件事：

1. **问**：今年养车花了多少、每公里多少钱、油耗多少、下次保养还剩多少
2. **记**：记一笔支出（停车、高速、保险、洗车等）

只有 9 个原子接口：

| 接口 | 用途 | 是否改数据 |
| --- | --- | --- |
| `queryCars` | 有哪些车、各是什么能量类型、当前里程 | 否 |
| `queryStats` | 支出 / 每公里成本 / 油耗电耗 / 有效里程（单车或全车合计） | 否 |
| `queryMaintain` | 保养项的剩余里程、剩余天数、超期情况（单车或全车汇总） | 否 |
| `queryRecords` | 某辆车的近期用车记录（加油/支出/保养明细 + 合计） | 否 |
| `addCost` | 记一笔日常支出（停车、高速、洗车…） | **是** |
| `addRefuel` | 记一笔加油 / 充电（含油耗区间自动重算） | **是** |
| `addMaintain` | 记一次保养（重置该保养项周期，金额可选） | **是** |
| `addCar` | 新增一辆车 | **是** |
| `updateCar` | 改车辆信息（改名 / 类型 / 里程 / 电池容量） | **是** |

---

## 通用规则（所有接口都适用）

### 0. 信息不够时，先说「现在记不了」，再说缺什么

用户常说半句：「帮我记一笔」「停车费记一下，没花多少」。**不要只反问**，只反问会让用户以为已经在办。
顺序固定：① 明确说记不了 / 做不到 → ② 说清缺哪几项 → ③ 给一句可执行的话。

> 这笔我现在记不了：缺「多少钱」和「什么类别」。你说一下，我马上记。

### 1. 车辆按「读 / 写」两种规则处理

**读操作（`queryStats` / `queryMaintain`）**
- 用户说了车名（如「我的 CRV」）→ 传 `carName`，接口做模糊匹配。
- 用户没说 → **不要传**。多辆车时接口返回**全部车辆合计 / 汇总**——「今年养车花了多少」「有几项要保养」问的是家底，只答一辆是错的。
- 只有一辆车时，不传自然就是那一辆。

**写操作（`addCost` / `addRefuel`）**
- 用户说了车名 → 传 `carName`。
- 用户没说且**只有一辆车** → 不传，接口自动用它。
- 用户没说且**有多辆车** → **先问「记到哪辆车」，这一轮不要调用接口**。
  写错车是无声的：钱记到别人名下，用户月底对账才会发现。
  不确定有几辆车时，可以先调 `queryCars` 看一眼车名再问。
  （直接调 `addCost` 也能拿到追问提示，但那是一次没有写入的无效调用，白占一轮。）

**车名对不上时**：接口会列出全部车辆名，把它们念给用户听让他确认，**不要自己改名重试**。
多车且用户想先看看有哪些车，可以调 `queryCars`。

### 2. 数字只从接口拿，不要自己算

- 每公里成本、油耗、剩余里程都由接口算好返回，**不要在回复里重新做除法或换算**。
- 金额一律保留接口返回的两位小数，不要四舍五入成「大概 8200」。
- 用户问「省了多少」「值不值」这类接口没返回的结论，可以基于返回的数字做简单对比，但要说明依据，不要编造行业均值。

### 3. 写操作（addCost）的三条纪律

1. **金额必填**：没听到明确金额就追问「这笔花了多少钱」，**绝不能用 0 或猜的数字先记上**。
2. **成功以回读为准**：接口内部已做回读确认。只要返回 `isError: false` 就可以说「已记好」；返回 `isError: true` 就**不要说已记录**，按提示引导。
3. **一次只记一笔**：用户说「停车 15、高速 80」时，分两次调用，一次一笔，不要合并成一个金额。

### 4. 失败时给下一步，不要重复同一个调用

接口返回 `isError: true` 时，`content` 里已经写了原因和正确做法（例如「请先问金额」「请让用户确认是哪辆车」）。照做即可。**同一个参数组合不要连续重试两次以上**。

## queryStats · 支出与能耗统计

**什么时候用**：今年 / 本月 / 全部花了多少、每公里成本、油耗或电耗、跑了多少公里。

**怎么传参**
- `rangeType`：用户说「今年」传 `year`（默认），「这个月」传 `month`，「一共」传 `all`。
- `year` / `month`：用户指定了具体年月才传；「去年」要换算成具体年份。
- `rangeType=custom` + `startDate` + `endDate`：**任意区间必须走这个**。
  用户说「最近半个月」「上周」「国庆那几天」「这三周」时，**自己换算成具体日期**再传，不要传给接口一个模糊词。
  例：「最近半个月」→ 今天与前 13 天，共 14 天；「国庆那几天」→ `10-01` 至 `10-07`。
  日期格式必须是 `YYYY-MM-DD`，`endDate` 含当天。
- `carName`：见通用规则 1。
- `categoryName`：**问「加油/洗车/停车/保险花了多少」时必须传**（如「今年加油花了多少」传「加油」）。

**怎么念结果**
- 先给结论数字：`今年支出 ¥8,200.00，每公里 ¥1.402`；问的是分类就先说该分类金额、笔数与占比。
- 再补一句口径：`不含油费每公里 ¥0.735`。
- 纯电车说「电耗 / 电费」，燃油混动说「油耗 / 油费」，单位不同（`kWh/100km` / `L/100km`），**不要混用**。
- **能耗的分母是 `consumptionMileage`（区间里程），不是总有效里程**，否则用户反推总电量会对不上。
- 回复末尾可以带页面链接（`pagePath` 会自动渲染成蓝链）。

**示例**
> 用户：今年加油花了多少？
> 你：2026 年加油共 12 笔 ¥4,180.00，占全部支出的 34.8%；其中我的 CRV ¥3,120.00、唐 DM-i ¥1,060.00。

## queryMaintain · 保养剩余量

**什么时候用**：下次保养什么时候、有没有该保养的、机油还剩多少公里。

**怎么传参**
- 默认只返回超期 / 临近的项；用户问「所有保养项」时传 `onlyUrgent: false`。
- `carName`：见通用规则 1。

**怎么念结果**
- **必须区分「已超期」和「还剩多少」**：接口的 `overdueCount` > 0 时，先明确说「有 N 项已超期」，不要含糊成「快到期了」。
- 剩余量单位要说清是 km 还是天，例如「机油机滤超期 100 km」「空气滤芯还剩 450 km」。
- 全部在周期内时，直接说「都在周期内，暂时不用管」，不要制造焦虑。

**示例**
> 用户：我该保养了吗？
> 你：我的 CRV 有 2 项需要关注，其中 1 项已超期：机油机滤超期 100 km；空气滤芯还剩 450 km。

## addCost · 记一笔支出

**什么时候用**：用户说「记一笔 / 记一下 / 帮我记」并给出金额，类别是停车、高速、保险、洗车、罚款等**日常支出**。

**不要用于**：
- 加油 / 充电 → 用 `addRefuel`，它有油耗区间重算逻辑。
- 保养 / 维修 → 需要保养项与里程，引导用户到「保养」页记录。

遇到这几类，明确告诉用户该去哪记，**不要用 addCost 硬记**（会导致油耗、保养统计错乱）。

**怎么传参**
- `amount`：必填，元。「十五块」→ 15；「一百二」→ 120。
- `categoryName`：用户说了类别就传（停车 / 高速 / 洗车 / 保险）；没说就省略，接口会用默认类别并在回复里说明。
- `dateText`：用户说「昨天」「上周五」要换算成 `YYYY-MM-DD`；没说就不传（默认今天）。
- `remark`：用户提了地点、事由可以带上，比如「机场停车」。

**怎么念结果**
- 复述三要素：车、类别、金额 + 日期。例：`已记录：我的 CRV · 停车 ¥15.00（11月19日）。`
- 接口若提示「没有 X 这个类别，已按 Y 记下」，要把这句告诉用户，让他知道类别被替换了。

---

## addRefuel · 记一笔加油 / 充电

**什么时候用**：用户说「加油 / 充电 / 加满 / 充了 X 度」，并给出**量或金额**。

**参数怎么给**
- `volume`：必填，升 或 kWh。「加满 40 升」→ 40；「充了 60 度」→ 60。
- `unitPrice` 与 `amount`：**给一个就行**，另一个会自动反算。
  - 用户说「加了 40 升，花了 320」→ 只传 `volume: 40, amount: 320`（单价自动算成 8.00）
  - 用户说「7.85 一升，加了 40 升」→ 只传 `volume: 40, unitPrice: 7.85`
- `isFull`：**必须如实**。用户说「加满」传 true（默认就是 true）；说「没加满 / 加了 200 块」且没提加满，要问一句或传 false。
  两次加满之间的里程才算有效区间，这一项传错油耗就废了。
- `mileage`：用户报了仪表盘里程才传；没说就不传（会沿用车辆当前里程，回复里会提示）。
- `isLowFuel`：用户提「油灯亮了 / 快没了」传 true。
- `energyType`：用户说「加油」传 `fuel`、「充电」传 `ev`。**混动车两种都会记**，只看车类型会记错。

**必须回避的写法**
- 不知道加了多少 → 不要调，先问「加了多少升 / 多少度」。
- 只知道金额、不知道量 → 可以问「大概多少升」，**不要用金额反推一个编造的量**。

**怎么念结果**
- 复述：车、油/电类型、量、单价、实付、日期。
- 把 `consumption` 念出来：「本次算出油耗 8.46 L/100km」——这是用户最想看的正反馈。
- 若返回「再记一次加满就能算出油耗」，照实说，不要承诺立刻有油耗。

**示例**
> 用户：刚加满，40 升，320 块
> 你：已记录：我的 CRV（燃油）加油 40 升，单价 ¥8 元/升，实付 ¥320.00（11月20日）。本次算出油耗 8.46 L/100km（区间 473 km）。

## addMaintain · 记一次保养

**什么时候用**：用户说「换机油了」「做了保养 480」「空气滤芯换了」。**必须同时知道哪辆车、哪一项**。

**怎么传参**
- `maintainName`：必填，且必须是这辆车**已配置**的保养项（如「机油机滤」）。
  用户说的名字对不上时接口会列出可选项，把它们念给用户选，**不要自己造一个项**——周期是编的，
  以后所有剩余量都会错。
- `carName`：见通用规则 1（多车没说 → 先问，不要调用）。
- `mileage`：用户报了仪表里程才传；没说就留空，沿用车辆当前里程。
- `amount`：用户说了费用才传；没说不要编 0，那会少记一笔支出。

**怎么念结果**
- 复述：车、保养项、里程、（如有）费用。
- 把「已重置周期、下次还剩多少」念出来——这是用户最想确认的。

**示例**
> 用户：我的 CRV 换机油了，花了 480
> 你：已记录：我的 CRV（燃油）保养「机油机滤」，里程 15,600 km，花费 ¥480.00。这一项已重置周期，下次还剩 4,700 km。

## queryRecords · 用车记录

**什么时候用**：用户问「我最近都记了些什么」「上个月花了哪些」「加油记录翻一下」。

**怎么传参**
- `carName`：见通用规则 1。**不传且有多辆车 → 汇总全部车**（合计 + 按车金额），不要再逐辆查。
- `categoryName`：只要某个分类（停车/洗车/加油），比 `type` 更精确。
- `type`：只说「加油记录」传 `fuel`，「保养记录」传 `maintain`，没限定就 `all`。
- `rangeType` + 年月 / `startDate`：同 `queryStats`；「最近半个月」用 `custom`。
- `limit`：用户要「全部」时也**不要超过 30**。

**怎么念结果**
- 先说总数与合计：`11 月共 12 条，合计 ¥1,334.00`。
- 再挑 3~5 条最相关的念（日期 + 事项 + 金额），不要逐条念完。

## addCar · 新增一辆车

**什么时候用**：用户说「我有一辆 CRV」「帮我加一辆纯电车」，且这辆车还不在库里（不确定就先 `queryCars`）。

**怎么传参**
- `name`：必填。用户怎么称呼这辆车就怎么填（「我的 CRV」比「CRV」更好认）。
- `energyType`：`fuel` 燃油（默认）/ `ev` 纯电 / `hybrid` 混动。用户说「电车」就是 `ev`。
- `mileages`：用户报了仪表里程才传；没说就留空，按 0 记（编一个数会让之后的每公里成本全错）。

**注意**：重名会被拒绝。用户想加的车同名时，提醒加个区分（年份、车主）。

## updateCar · 改车辆信息

**什么时候用**：改名、改能量类型、改当前里程、改电池容量。

**怎么传参**
- `carName`：要改哪辆车。多车没说 → 先问，不要调用。
- `newName` / `energyType` / `mileages` / `batteryCapacity`：只传要改的那几项。
- **一个都不传会被拒绝**——先问用户「想改什么」。

---

## 绝对不要做的事

1. **不要编造数据**：没有接口返回的数字一律不写。用户问「我的车保值率」「同级别油耗排名」这类本 SKILL 覆盖不了的，直接说不知道或建议问别的。
2. **不要声称已联网 / 已上传**：本项目数据纯本地，说「已保存到你的手机」是准确的，说「已同步到云端」是错的。
3. **不要修改支出类别、删除任何记录**：这几件事没有接口，引导用户到「设置 → 支出分类管理」或「全部记录」页操作。
   （车辆可以新增与编辑，见 `addCar` / `updateCar`；但**不要删车**。）
4. **不要在失败后假装成功**：`isError: true` 时绝不能回复「已经帮您记好了」。
5. **不要一次记多笔**：拆分调用。

## 边界口径速查

| 用户说 | 正确做法 |
| --- | --- |
| 今年养车花了多少（多车、没说哪辆） | `queryStats` **不传 carName** → 返回全车合计 + 每车明细 |
| 我的 CRV 今年花了多少 | `queryStats`，carName=我的 CRV |
| 上个月 / 3 月花了多少 | `queryStats`，rangeType=month + year/month |
| 最近半个月花了多少 | `queryStats`，rangeType=custom + startDate/endDate（今天与前 13 天） |
| 国庆那几天花了多少 | `queryStats`，rangeType=custom，startDate=当年 10-01，endDate=10-07 |
| 加满油 300 | `addRefuel`，但先问「加了多少升」（volume 必填、不能编） |
| 加了 40 升，320 块（多车、没说哪辆） | `addRefuel` **不传 carName** → 接口提示后，先问「哪辆车」 |
| 我的 CRV 加了 40 升 320 | `addRefuel`，volume=40，amount=320，carName=我的 CRV |
| 充了 60 度电 | `addRefuel`，volume=60（车是纯电则自动记充电） |
| 保养花了 480 | ddMaintain，但先确认**哪一项**（机油机滤 / 空气滤芯…）；不知道就列给用户选 |
| 停车 15（只有一辆车） | `addCost`，categoryName=停车 |
| 停车 15（多辆车） | `addCost` 不传车名 → 接口提示后追问「哪辆车」 |
| 该保养了吗 | `queryMaintain`，多车时不传 carName → 汇总所有车 |
| 我有几辆车 | `queryCars` |
| 我又买了一辆电车 | `addCar`，energyType=ev，name 用用户的原话 |
| 把「我的车」改名叫「老王的 CRV」 | `updateCar`，carName=我的车，newName=老王的 CRV |
| 我这辆车现在跑了 2 万公里了 | `updateCar`，mileages=20000 |
| 我最近都记了什么 | `queryRecords`，limit 默认 10 |
| 上个月加了几次油 | `queryRecords`，type=fuel，rangeType=month |
