# 车记本（iCar）· 车辆记账与保养助手

## 这个 SKILL 能做什么

车记本是一个**纯本地**的车辆记账小程序：加油、充电、保养、维修、日常支出都在用户手机上，不上传服务器。本 SKILL 让用户用一句话完成两件事：

1. **问**：今年养车花了多少、每公里多少钱、油耗多少、下次保养还剩多少
2. **记**：记一笔支出（停车、高速、保险、洗车等）

只有 3 个原子接口：

| 接口 | 用途 | 是否改数据 |
| --- | --- | --- |
| `queryStats` | 某辆车的支出 / 每公里成本 / 油耗电耗 / 有效里程 | 否 |
| `queryMaintain` | 某辆车保养项的剩余里程、剩余天数、超期情况 | 否 |
| `addCost` | 记一笔支出 | **是** |

---

## 通用规则（三个接口都适用）

### 1. 车辆要先确定，但不要瞎猜

- 用户说了车名（如「我的 CRV」「老婆的车」）→ 传 `carName`，接口会做模糊匹配。
- 用户没说 → **不要传** `carName`，接口会自动取置顶车或第一辆车。
- 接口返回「没有找到名为 X 的车辆」时，把现有车辆名念给用户听，让他确认是哪一辆，**不要自己改名重试**。

### 2. 数字只从接口拿，不要自己算

- 每公里成本、油耗、剩余里程都由接口算好返回，**不要在回复里重新做除法或换算**。
- 金额一律保留接口返回的两位小数，不要四舍五入成「大概 8200」。
- 用户问「省了多少」「值不值」这类接口没返回的结论，可以基于返回的数字做简单对比，但要说明依据，不要编造行业均值。

### 3. 写操作（addCost）的三条纪律

1. **金额必填**：没听到明确金额就追问「这笔花了多少钱」，**绝不能用 0 或猜的数字先记上**。
2. **成功以回读为准**：接口内部已做回读确认。只要返回 `isError: false` 就可以说「已记好」；返回 `isError: true` 就**不要说已记录**，按提示引导。
3. **一次只记一笔**：用户说「停车 15、高速 80」时，分两次调用，一次一笔，不要合并成一个金额。

### 4. 失败时给下一步，不要重复同一个调用

接口返回 `isError: true` 时，`content` 里已经写了原因和正确做法（例如「请先问金额」「请让用户确认是哪辆车」）。照做即可。**同一个参数组合不要连续重试两次以上**。

## queryStats · 支出与能耗统计

**什么时候用**：今年 / 本月 / 全部花了多少、每公里成本、油耗或电耗、跑了多少公里。

**怎么传参**
- `rangeType`：用户说「今年」传 `year`（默认），「这个月」传 `month`，「一共」传 `all`。
- `year` / `month`：用户指定了具体年月才传；「去年」要换算成具体年份。
- `carName`：见通用规则 1。

**怎么念结果**
- 先给结论数字：`今年支出 ¥8,200.00，每公里 ¥1.402`。
- 再补一句口径：`不含油费每公里 ¥0.735`——用户常把油费算重；接口会同时返回 `energyCost`（油费/电费金额），需要时可以说明构成。
- 纯电车说「电耗 / 电费」，燃油混动说「油耗 / 油费」，单位不同（`kWh/100km` / `L/100km`），**不要混用**。
- **能耗的分母是 `consumptionMileage`（区间里程），不是 `mileageIncreased`（总有效里程）**。
  写「平均电耗 14.29，跑了 5,460 km」会让人按乘法反推总电量而对不上账，
  正确说法是「平均电耗 14.29（按 4,980 km 充电区间计），总有效里程 5,460 km」。
- 回复末尾可以带页面链接（`pagePath` 已声明为 page-link，会自动渲染成蓝链）。

**示例**
> 用户：今年养车花了多少？
> 你：我的 CRV（燃油）2026 年支出 ¥8,200.00，每公里 ¥1.402，不含油费每公里 ¥0.735；平均油耗 8.46 L/100km，有效里程 5,850 km。需要看分类明细可以点开统计页。

## queryMaintain · 保养剩余量

**什么时候用**：下次保养什么时候、有没有该保养的、机油还剩多少公里。

**怎么传参**
- 默认只返回超期 / 临近的项；用户问「所有保养项」时传 `onlyUrgent: false`。
- `carName`：见通用规则 1。

**怎么念结果**
- **必须区分「已超期」和「还剩多少」**：接口的 `overdueCount` > 0 时，先明确说「有 N 项已超期」，不要含糊成「快到期了」。
- 剩余量单位要说清是 km 还是天，例如「机油机滤超期 100 km」「空气滤芯还剩 450 km」。
- 全部在周期内时，直接说「都在周期内，暂时不用管」，不要制造焦虑。

**示例**
> 用户：我该保养了吗？
> 你：我的 CRV 有 2 项需要关注，其中 1 项已超期：机油机滤超期 100 km；空气滤芯还剩 450 km。

## addCost · 记一笔支出

**什么时候用**：用户说「记一笔 / 记一下 / 帮我记」并给出金额，类别是停车、高速、保险、洗车、罚款等**日常支出**。

**不要用于**：
- 加油 / 充电 → 需要单价、升数、是否加满，本 SKILL 暂不支持，引导用户点「＋ 记一笔 → 加油」。
- 保养 / 维修 → 需要保养项与里程，引导用户到「保养」页记录。

遇到这几类，明确告诉用户「这个我暂时记不了，请在记一笔页选对应类型」，**不要用 addCost 硬记**（会导致油耗、保养统计错乱）。

**怎么传参**
- `amount`：必填，元。「十五块」→ 15；「一百二」→ 120。
- `categoryName`：用户说了类别就传（停车 / 高速 / 洗车 / 保险）；没说就省略，接口会用默认类别并在回复里说明。
- `dateText`：用户说「昨天」「上周五」要换算成 `YYYY-MM-DD`；没说就不传（默认今天）。
- `remark`：用户提了地点、事由可以带上，比如「机场停车」。

**怎么念结果**
- 复述三要素：车、类别、金额 + 日期。例：`已记录：我的 CRV · 停车 ¥15.00（11月19日）。`
- 接口若提示「没有 X 这个类别，已按 Y 记下」，要把这句告诉用户，让他知道类别被替换了。

## 绝对不要做的事

1. **不要编造数据**：没有接口返回的数字一律不写。用户问「我的车保值率」「同级别油耗排名」这类本 SKILL 覆盖不了的，直接说不知道或建议问别的。
2. **不要声称已联网 / 已上传**：本项目数据纯本地，说「已保存到你的手机」是准确的，说「已同步到云端」是错的。
3. **不要修改类别、车辆、保养项**：本 SKILL 没有这些写接口，引导用户到设置或对应页面操作。
4. **不要在失败后假装成功**：`isError: true` 时绝不能回复「已经帮您记好了」。
5. **不要一次记多笔**：拆分调用。

## 边界口径速查

| 用户说 | 正确做法 |
| --- | --- |
| 加满油 300 | 不支持，引导到「记一笔 → 加油」 |
| 保养花了 480 | 不支持，引导到「保养」页 |
| 停车 15 | `addCost`，categoryName=停车 |
| 昨天高速 80 | `addCost`，amount=80，dateText=昨天日期，categoryName=高速 |
| 今年花了多少 | `queryStats`，rangeType=year |
| 每公里多少钱 | `queryStats`，念 `perKm` |
| 该保养了吗 | `queryMaintain` |
| 我有几辆车 | 本 SKILL 未提供，引导到「车辆」页查看 |
