# iCar V2 任务清单

> 依据：《软件设计报告 V1.3》第 15.6 节「未实现清单与建议优先级」。

## 0. 使用说明

**优先级**

| 级别 | 含义 | 处理策略 |
| --- | --- | --- |
| P1 | 体验缺口，用户可感知 | 优先做，1 个迭代内完成 |
| P2 | 能力扩展，提升完整性 | 排入第二迭代 |
| P3 | 平台化 / 依赖外部资源 | 视云环境与资质推进 |

**状态标记**：`待开始` / `进行中` / `已完成` / `已验收`

**任务编号**：`V2-xx`，与设计报告 15.6 的优先级项一一对应，末尾 `T-xx` 为技术债。

**通用验收要求**（所有任务适用）：

- `npm run typecheck` 无错误
- `npm test` 全绿，新增逻辑需补单测
- 微信开发者工具「清缓存 → 重新编译」后可正常运行
- 不破坏既有 44 个用例与四类记录闭环

## 2. 迭代一：体验补全（P1）

### V2-01 维修图片上传与持久化

**目标**：记维修支持最多 3 张图片，压缩后本地持久化；记录列表显示缩略图；编辑时可回显与增删。

**改动文件**

| 文件 | 改动 |
| --- | --- |
| `pages/repair-form/index.ts` | 加载/回填 `images`，新增选择、删除、预览 |
| `pages/repair-form/index.wxml` / `.wxss` | 九宫格上传区（`0/3` 计数） |
| `services/repair.service.ts` | `saveRepair` / `updateRepair` 落 `images`；`removeRepair` 删文件 |
| `pages/records/index.ts` / `.wxml` | 维修卡片缩略图 |
| `utils/image.ts` | 新增：`chooseAndCompress()` / `removeImages()` |

**实现要点**

1. `wx.chooseMedia({ count: 3 - 已有, mediaType: ['image'] })`
2. `wx.compressImage({ quality: 70 })` 后 `fs.copyFileSync` 到 `wx.env.USER_DATA_PATH/repair/<recordId>/<uuid>.jpg`
3. `RepairRecord.images` 存**相对路径或文件名**（便于导出/迁移，不要存临时路径）
4. 删除维修记录时同步删目录（失败不阻塞，仅日志）
5. 点击缩略图 `wx.previewImage`

**验收标准**

- [ ] 最多选 3 张，超出禁用加号
- [ ] 保存后重进编辑页图片回显
- [ ] 记录列表显示缩略图，点击可预览
- [ ] 删除记录后对应图片目录被清理
- [ ] 图片不进 Storage（不占 10MB 配额）

**风险**：`copyFileSync` 在部分机型对临时路径兼容性差，需兜底用 `tempFilePath`。

## 4. 迭代三：平台化（P3）

### V2-13 云开发接入（登录 / 同步 / 订阅消息 / 油价 / 反馈）

**目标**：从纯本地升级为「本地优先 + 云增强」。

**改动文件**

| 文件 | 改动 |
| --- | --- |
| `cloudfunctions/login/` | 新增，返回 openid |
| `cloudfunctions/sync/` | 新增，`push` / `pull`，含 tombstone 与冲突解决 |
| `cloudfunctions/reminder/` | 新增，`syncQueue` + `cronPush`（定时触发器 08:00） |
| `cloudfunctions/oilprice/` | 新增，油价代理 + 30 分钟缓存 |

**验收标准**

- [ ] 两台设备同步后数据一致，删除可传播

**依赖**：云开发环境、订阅消息模板资质、`appid` 完成主体认证。

### V2-15 应用锁 + 数据加密

**目标**：补齐 NFR-04 的 V2 部分。
