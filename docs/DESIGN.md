# iCar 界面设计规范（WXSS 版）

> 建立于 2026-11-08，依据同日 UI 一致性审计。本文是**给人和 AI 编码 agent 共同阅读的设计说明书**：
> 新增或修改任何 WXML/WXSS 前先读本文；与 `docs/软件设计报告.md` 第 6 章冲突时，以本文为**落地口径**，设计报告 6.1 保留为需求原本。
>
> 本文只约束视觉表现，不涉及数据口径与业务逻辑；`npm test` 不覆盖样式，改动后须真机走查。

## 1. 适用范围与技术约束

| 项 | 约束 |
| --- | --- |
| 技术栈 | 微信小程序原生 WXML + WXSS，非 Web HTML/CSS |
| 单位 | 普通声明统一用 `rpx`（750rpx = 屏宽）；**但 `app.wxss` 的自定义属性只能用 `px` 或 hex 单值** —— WXSS 编译器对含 `rpx` / `rgba()` / 逗号的变量值兼容性不稳，曾导致全局样式异常。因此 `--radius-*` / `--space-*` 与新增令牌统一为 `px`（按 375px 屏与 rpx 等价换算） |
| 作用域 | `app.wxss` 全局作用于页面；**自定义组件默认样式隔离**，组件内需自行引令牌或传值 |
| Canvas | **Canvas 2D 上下文不解析 CSS 变量**，`fillStyle`/`strokeStyle` 只能写字面量 → 必须引用 `utils/chart-draw.ts` 导出的 `CHART_THEME`，不得写死色值 |
| 安全区 | 底部固定元素用 `env(safe-area-inset-bottom)`；页面底部留白 ≥ `160rpx + 安全区` |
| 深色模式 | 首版不支持，不要引入 `prefers-color-scheme` |
| 共享模块 | 新增 `utils/` 小模块前先确认开发者工具能编译产出 js（曾因 `chart-theme.ts` 未产出 js 导致全站白屏）。**优先并入已有且验证可加载的模块**；避免 `as const` / `satisfies` 等较新语法，内置 TS 插件版本可能落后。新增/删除模块后必须跑 import 可解析性检查（已固化为 `tests/chart-theme.test.ts`） |

## 3. 字号、间距、圆角阶梯

新增代码**只从下列档位取值**，不要再引入第 20 种字号。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--font-xs` | `11px`（22rpx） | 角标、极小说明 |
| `--font-sm` | `12px`（24rpx） | 辅助文字、标签、轴标签 |
| `--font-md` | `14px`（28rpx） | 正文、表单值、按钮 |
| `--font-lg` | `16px`（32rpx） | 卡片标题、小节标题 |
| `--font-xl` | `20px`（40rpx） | 指标数值、页面主标题 |

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--sp-1` | `4px`（8rpx） | 图标与文字间隙 |
| `--sp-2` | `8px`（16rpx） | 元素间距、控件内边距 |
| `--sp-3` | `12px`（24rpx） | 页面外边距、**卡片内边距基准** |
| `--sp-4` | `16px`（32rpx） | 卡片内左右留白、分组间距 |
| `--sp-5` | `24px`（48rpx） | 区块间距 |

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--r-sm` | `4px`（8rpx） | 小标签、分段项 |
| `--r-md` | `8px`（16rpx） | 卡片、输入框 |
| `--r-lg` | `12px`（24rpx） | 浮层、底部弹层 |
| `--r-pill` | `999px` | 胶囊按钮、标签 |

> 括号中为 375px 屏下的等价 `rpx` 值。令牌定义**必须**写 `px`（见第 1 节）；普通声明仍可直接写 `rpx`。

**卡片内边距统一 `var(--sp-3) var(--sp-4)`**；历史 `8rpx 32rpx` / `28rpx 32rpx` / `40rpx 32rpx` 三种写法逐步收敛，改动时顺手对齐。

## 4. 深度与层级

> **阴影不定义为自定义属性**（复合值含 `rgba()` 与逗号，WXSS 编译器支持不稳，曾导致全局样式异常）。
> 在使用处直接写字面量，属第 2 节允许的 `rgba()` 合理例外：
>
> - 普通卡片：`box-shadow: 0 2rpx 12rpx rgba(15, 23, 42, 0.05);`
> - 悬浮主按钮：`box-shadow: 0 10rpx 28rpx rgba(59, 111, 246, 0.40);`

层级顺序：页面底 → 卡片（白 + `--shadow-card`）→ 浮层/气泡（白 + 描边 `--color-border` + 略重阴影）→ 悬浮按钮。列表页**必须有卡片阴影**，否则一屏白卡片会糊成一片。

## 5. 组件状态（当前最大缺口）

每个可交互元素都要覆盖下表，缺一项视为未完成：

| 状态 | 做法 |
| --- | --- |
| 默认 | 按第 2/3 节令牌 |
| 按下 | WXML 加 `hover-class`，样式里降透明度到 `0.6` 或换 `--color-primary-dark` |
| 禁用 | `.is-disabled { opacity: .5; }` + 事件内 `return`，不要只靠视觉 |
| 加载 | 耗时操作（导入/导出）用 `wx.showLoading({ mask: true })` + `hideLoading`，禁止界面静止 |
| 空态 | 图标/符号 + 一句说明 + 引导动作，不能只有一行灰字 |
| 失败 | `wx.showToast({ icon: 'none' })` 给明确原因，见 `utils/save-guard.ts` |

**点击区域 ≥ 44×44pt**（NFR-06）：小图标、文字链接、卡片右上角「…」都要补 `padding` 撑开，不能只给文字本身绑定事件。

## 6. Canvas 图表专用

`components/{donut,line,bar}-chart/index.ts` 通过 `utils/chart-draw.ts` 的 `CHART_THEME` 取色，禁止内联 hex。

```ts
// 正确
ctx.fillStyle = CHART_THEME.primary;
// 错误
ctx.fillStyle = '#3B6FF6';
```

新增图表颜色时**同时**在 `app.wxss` 加 `--chart-*` 与 `chart-draw.ts` 的 `CHART_THEME` 加同值常量，两处用注释关联；`tests/chart-theme.test.ts` 校验两者一致。

字号在 canvas 里用逻辑像素（`10px sans-serif` 等），与 WXSS 的 rpx 阶梯无关，不要互相套用。

## 7. 布局原则

- 页面左右外边距 `24rpx`；卡片之间 `20rpx`；区块标题与内容之间 `16rpx`。
- 表单用「卡片分组」：基本信息 / 金额信息 / 选项，每组一个 `.card`，组间距 `20rpx`。
- 指标一律三列等分，数值用 `--font-xl` + `font-weight: 600`，标签用 `--font-sm` + `--color-text-3`。
- 底部有悬浮按钮的页面，`padding-bottom` 留 `200rpx + env(safe-area-inset-bottom)`。
- 不要用 `backdrop-filter` 做关键可读性依赖（低版本 Android 支持不稳）。

## 8. Do's and Don'ts

**Do**

- 新增样式先查第 2/3 节有没有现成令牌
- 颜色一律 `var(--*)`，尺寸一律 `rpx`
- **直接复用 `app.wxss` 的全局 `.card` / `.btn-primary` / `.empty-state` / `.hover-dim`**，页面内只写差异（如 `margin`），不要整块重定义
- 表单保存统一走 `utils/save-guard.ts` 的 `guardSave()`（自带异常兜底 + 600ms 防重复提交）
- 长按拖动、删除等破坏性操作给二次确认（回收站见 `services/recycle.service.ts`）

**Don't**

- 不要在 wxss 或 canvas TS 里写新的 hex
- 不要把 `px` 和 `rpx` 混用于同一语义（圆角、间距尤甚）
- 不要用暗色营销站风格：本项目是浅色工具型小程序，暗色仅用于 `--color-dark-card` 那张统计卡
- 不要照搬 Web 设计系统：Geist/SF Pro 等专有字体、112px 巨标题、全屏摄影、断点响应式都不适用
- 不要在自定义组件里假设能读到页面级 class（样式隔离）
- **不要在 `observers` 里无条件 `setData`**：observers 在首次接收属性时就触发（早于 `ready`），此时首帧未完成，会报 `Expected updated data but get first rendering data`。正确写法是在 `ready()` 里置 `this._ready = true`，observers 首行 `if (!this._ready) return`，初始绘制交给 `ready()`
- 不要只改颜色不改状态：点了没反馈比颜色不统一更伤体验

## 9. 图表标签避让（2026-11-08）

环形图外标签在小占比扇区相邻时会互相遮挡。已抽 `utils/chart-math.ts` 的 `layoutDonutLabels()`：

| 步骤 | 做法 |
| --- | --- |
| 分侧 | 按 `cos(mid) >= 0` 分左右，两侧独立避让 |
| 推开 | 每侧按 y 升序，自上而下保证相邻间距 ≥ 行高（14px） |
| 回压 | 末位越出下边界时自下而上回压，再兜一次底，保证全部落在画布内 |
| 引线 | 折点 y 跟随标签 y，引线不会交叉；起点固定在扇区外缘 |

**新增图表或改标签尺寸时**：`minGap` 必须 ≥ 标签行高，`minY` / `maxY` 留出行高一半的余量。

## 11. UI 质量诊断（八条，2026-11-09）

源自 *Refactoring UI* 的判断框架，已本地化为可直接量化的版本。**改任何界面前先跑一遍，改完再跑一遍对比分数。**

### 11.1 评分公式

```
单页得分 = 满足条数 / 8 × 10
```

| 分数 | 判定 |
| --- | --- |
| 10 | 八条全过，眯眼看层级清晰、灰度下也成立、所有取值都在刻度上 |
| 9 | 恰好 1 个缺口（通常是层级偏弱或留白不足） |
| 6–8 | 2–3 个缺口 |
| ≤5 | 4 个以上缺口（间距随意、靠颜色硬撑层级、对比度不达标） |

### 11.2 八条诊断（按可量化程度排序）

| # | 检查问题 | 不通过时改什么 | 本项目可量化指标 |
| --- | --- | --- | --- |
| 1 | 眯眼/模糊下，层级还读得出来吗 | 拉大主次对比（字号 / 字重 / 明度） | 文本字号档数：**3~6 档为合格**；<3 层次弱，>6 无节制 |
| 2 | 去色（灰度）后还成立吗 | 说明颜色在替层级打工，强化尺寸 / 字重 / 间距 | 是否使用 `font-weight` 等非颜色手段表达强调 |
| 3 | 留白够不够 | 大概率不够，加大间距，尤其「组与组之间」 | 卡片内边距 ≥ `var(--sp-3)`；页面左右 24rpx |
| 4 | 标签是否弱于数值 | 标签变小、变浅或降级 | `.metric-label` 字号 < `.metric-value` 字号 |
| 5 | 间距是否走同一刻度 | 只用第 3 节的阶梯值 | `padding`/`margin`/`gap` 中非阶梯值占比 < 10% |
| 6 | 文本行宽是否受限 | 限宽（小程序屏窄，多为天然合格） | 长文本容器是否有 `max-width` |
| 7 | **颜色对比度是否足够** | 白底换更深、深底换更浅 | **正文 ≥ 4.5:1，大字/图标 ≥ 3:1**；白底用 `text-3`，深底用 `text-4` |
| 8 | 阴影是否匹配高度层级 | 卡片有层次、弹层浮起 | 卡片有 `box-shadow` 或使用全局 `.card` |

| `vehicle-form` | 8.5 | 10 | 6 | 10 | 9 | 10 | 10 | **3** | 10 |

**结论：D7 是全部 20 页唯一的系统性缺口（全部 3 分）**，其余各项基本达标。D5 偏低的 4 个页面（`about` / `entry` / `maintain-manage` / `index`）是因为个别 `6rpx` / `60rpx` 微调值未入阶梯。

### 11.4 D7 根因与修复：`--color-text-3` 对比度不足

**修复前**实测（白底）：

| 令牌 | 值 | 白底对比度 | WCAG AA（4.5:1） |
| --- | --- | --- | --- |
| `--color-text-1` | `#1F2430` | 15.52:1 | ✅ |
| `--color-text-2` | `#5A6272` | 6.13:1 | ✅ |
| `--color-text-3` | `#9AA4B2` | **2.52:1** | ❌ |
| `--color-text-4` | `#8A93A6` | **3.09:1** | ❌ |
| `--color-primary` | `#3B6FF6` | 4.38:1 | ⚠️ 接近（白字在其上 4.38:1） |

`--color-text-3` 被引用 **56 处**，用于标签、辅助说明、只读值、箭头等。2.52:1 在强光/低端屏下基本不可读。

**已修复（2026-11-15，整体加深）**：

| 令牌 | 改动 | 白底 | 深底 `#1E2536` | 定位 |
| --- | --- | --- | --- | --- |
| `--color-text-3` | `#9AA4B2` → **`#6B7486`** | **4.70:1** ✅ | 3.25:1 ❌ | **白底**辅助文字（56 处） |
| `--color-text-4` | 保持 `#8A93A6` | 3.09:1 ❌ | **4.96:1** ✅ | **深底**辅助文字 / 装饰（4 处，全在车辆详情统计卡内） |

**关键方向性**：白底要深色、深底要浅色。加深 `text-3` 后它在深底反而降到 3.25:1，因此 `text-4` 保留且**限定为深底专用**——两者不是深浅顺位，而是**两种背景的反向配对**：

```
白底辅助文字  → --color-text-3 (#6B7486, 4.70:1)
深底辅助文字  → --color-text-4 (#8A93A6, 4.96:1)
```

层次校验：`text-2` 6.13 与 `text-3` 4.70 相差 1.43，层级未被压平。

同步改动：`utils/chart-draw.ts` 的 `CHART_THEME.text3`（有测试校验与令牌同值）、`custom-tab-bar/index.wxss`（样式隔离需字面量）。

`tests/contrast.test.ts` 已由「已知缺陷锁定」改为**正面对比度断言**，并新增两条边界约束：深底不得用 `text-3`、白底不得用 `text-4`（后者用全量扫描强制）。

### 11.5 AI 生成感的反模式（禁止出现）

以下五类是最典型的「一眼 AI」特征，均属**默认值而非选择**：

| # | 反模式 | 本项目的正确做法 |
| --- | --- | --- |
| 1 | 暖米色背景 + 高对比衬线 + 陶土色强调 | 项目基调是浅灰蓝（`#F5F6F8` / `#3B6FF6`），不要引入暖色系 |
| 2 | 近黑底 + 单一荧光绿/朱红强调 | 仅统计卡用深色，主色仍是蓝 |
| 3 | 报纸风（细线分隔、零圆角、密排多栏） | 圆角统一 8/16/24rpx，禁止零圆角卡片 |
| 4 | **SaaS 卡片套件**：所有内容切成同样的圆角卡片、全站同一圆角、同样 `rgba(0,0,0,.1)` 柔阴影、渐变当装饰 | 用 `.card` 但**用留白和字号区分层级**，不要靠"每块都套卡片" |
| 5 | 模板痕迹：每个标题上方都加全大写小标签、`A · B · C` 用中点连接、链接文字都加 `→` | 文案不带装饰性前标/后缀；分隔符按语义选择 |

**裁决原则**：brief 明确指定了风格就严格执行；brief 留空的自由度，**不要花在上述默认值上**。

## 12. 图标体系（2026-11-15）

### 12.1 预设图标按用途分组

图标从扁平 20 个改为 5 组 53 个，定义在 `utils/icons.ts` 的 `ICON_GROUPS`；选择器末尾另有第 6 个「自定义」分栏承载用户上传的图标。

| 分栏（2 字） | 覆盖内容 |
| --- | --- |
| 能源 | 燃油、充电、电池相关支出 |
| 养护 | 洗车、贴膜、保养、维修、轮胎 |
| 通行 | 停车、高速、票据、保险、罚单 |
| 车型 | 轿车 / SUV / MPV / 皮卡 / 跑车 / 摩托 |
| 其他 | 改装、灯光、装饰 |
| 自定义 | 用户上传并裁剪过的图标（可长按删除） |

**标签必须是 2 个汉字**：6 个分栏在 686rpx 可用宽内单行放下（合计 600rpx）；4 字标签会溢出到 712rpx，被迫引入横向滚动。

**规则**：新增图标必须进对应分组，不要另起一个「杂项」；同组内不得重复（`wx:key="*this"` 要求唯一，已有测试锁定）。

**关于颜色**：emoji 车型自带固有色，无法指定任意颜色。需要特定颜色时用自定义上传 + 裁剪。

**必须避开 Unicode 13 及更新的 emoji**（🪣🪟🪛🪫🪞🪙 等）：这些字符在 Android 10 及更早系统上无字形，会渲染成「豆腐块」。选图标时以 Emoji 12 及更早为准。唯一例外是 `🛻`（皮卡）——没有更早的等价字符，且是用户明确需要的车型，已知在旧设备上可能显示为方框（`tests/icon-crop.test.ts` 有断言锁定这份名单）。

### 12.2 自定义图标必须是正方形位图

| 约束 | 值 | 理由 |
| --- | --- | --- |
| 输出尺寸 | 256×256 px | 图标实际渲染 20~30px，256 已满足 2 倍屏以上；不乘 dpr，避免文件无谓变大 |
| 格式 | PNG | 透明背景需要 |
| 取景 | 强制 1:1 正方形，铺满视口 | 非正方形图在 `<image>` 里会被拉伸或留白 |

裁剪实现见 `pages/icon-crop` + `utils/image-crop.ts`（纯几何计算，已单测穷举）。

**图标区高度固定 208rpx（正好两行）**：切换分栏时图标数量不同，若用 `max-height` 面板会上下跳动。固定高度 + 内部滚动，面板总高恒定；空态也要撑满 208rpx。

自定义图标登记在 `customIcons` 表（`services/custom-icon.service.ts`），**不参与数据导出**——导出的只是 `wxfile://` 路径，换设备后文件不存在，带过去只会得到空白图标。该表同时进入启动清理的保留集，否则用户的图标库会被当成孤儿删掉。

### 12.3 沉浸式深色页（例外）

`pages/icon-crop` 是**全站唯一的沉浸式深色页**——看图片时浅色背景会干扰判断。

- 页面底色用既有 `--color-dark-card`，**不新增令牌**
- 若将来还有同类页面（图片预览、全屏图表），复用该令牌，不要各自造一个近似深色
- 该页 WXSS 仍受「禁止内联 hex」约束（见 `tests/chart-theme.test.ts`）

## 13. 皮肤体系（2026-11-18 增补）

### 13.1 三套皮肤

| key | 名称 | 定位 |
| --- | --- | --- |
| a | 极简线稿 | 纯白底 + 近黑字，默认 |
| b | 杂志封面 | 暖米白 + 陶土红强调 |
| c | 深色运动 | 近黑底 + 提亮蓝 |

令牌定义在 `utils/skin.ts` 的 `SKIN_TOKENS`，通过 `<page-meta page-style>` 注入到 `page` 节点。
页面 WXSS 仍只使用 `var(--color-*)`，切换皮肤不触碰任何布局。

### 13.2 与本文档既有约束的关系

- **第 2 节的令牌清单**：`app.wxss` 的 `page{}` 仍是默认值（= 皮肤 a 的基准），
  皮肤 b / c 是它的运行时覆盖，不新增任何选择器。
- **第 11.2 节 D7 对比度**：正文 ≥ 4.5:1 的约束对三套皮肤**同样适用**，
  `tests/skin.test.ts` 用同一套 WCAG 公式逐皮肤断言 text-1 / 2 / 3。
  注意皮肤 a 的 `--color-text-3` 必须与 `app.wxss` 同值（`#6B7486`），
  写成旧值 `#8A93A6` 会在运行时覆盖全局、撤销 2026-11-15 的对比度修复。
- **第 12.3 节「全站唯一沉浸式深色页」**：该结论只对**默认皮肤**成立。
  皮肤 c 下整站转深色，属于「主题」维度，与 icon-crop 的「单页沉浸式」不冲突。

### 13.3 已知取舍

1. **深色皮肤的实色按钮**：`--color-primary` 取 `#5B8CFF` 以保证深底上的文字可读（6.6:1），
   代价是白字在按钮上为 3.16:1，低于正文 4.5:1。按钮有明确边界与图标辅助，接受此取舍；
   若要完全合规，应把按钮底色改用 `--color-primary-dark`。
2. **皮肤 c 的部分令牌使用 rgba**（divider / fill / border / *-light / *-bg）：
   这些值经 `page-style` 内联注入，不经过 WXSS 自定义属性编译，
   因此不受「app.wxss 变量必须单值 hex」的约束；`app.wxss` 内仍保持全 hex。
3. **`--color-on-dark-*` 用实色而非半透明**：WXSS 变量值不能含逗号，
   改用「白色 62% / 38% 叠在 `#1E2536` 上」的等效实色（`#A9ACB2` / `#737882`）。
