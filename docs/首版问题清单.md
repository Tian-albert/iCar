### 15.2 根因（用户提供 Console 报错后确认）

```
module 'utils/chart-theme.js' is not defined, require args is './chart-theme'
    at chart-draw.ts:12
    at <require(utils/chart-draw.js)>
    at components/donut-chart/index.ts:2
```

**真实根因**：UI 打磨批次新增的 `utils/chart-theme.ts` 未被编译产出 `chart-theme.js`，而 `chart-draw.ts` 与三个图表组件都 `require` 它，于是加载即抛错 → 统计页图表组件初始化失败 → 页面渲染中断显示空白。

关键线索：`chart-draw.js` **能**加载（说明新文件本身可被编译），只是它依赖的 `chart-theme` 模块不存在。该文件用了 `as const` 断言，开发者工具内置 TS 编译插件版本较旧时可能编译失败且不产出 js，但 import 语句仍被保留。

> 此前一轮基于「WXSS 自定义属性形态」的推断**是错的**。那轮改动（令牌回退 px、阴影改字面量、TabBar 改字面量）本身是合理加固，但并非空白的原因；`custom-tab-bar` 的样式隔离问题是同期发现的**真实缺陷**，保留修复。

### 15.7 教训

静态检查（typecheck / 单测 / lint）**发现不了**「模块编译失败但 import 保留」这类问题：TS 层面引用完全合法，只有小程序的运行时 require 才会暴露。因此新增共享模块时：

1. 优先并入已有且被验证可加载的模块，不要为了「单一职责」新增小文件
2. 避免 `as const`、`satisfies` 等较新语法，开发者工具内置 TS 版本可能落后于 `node_modules`
3. 任何新增/删除模块后，跑一遍 import 可解析性检查（已固化为单测）
