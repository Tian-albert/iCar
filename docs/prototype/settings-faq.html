常见问题
数据与备份
数据存在哪里？会不会丢？ ›
全部存在你手机本地，不上传服务器，也不经过我们的服务器。 这意味着：卸载小程序、清理微信存储、换手机，数据都会消失。 建议定期到「数据导入导出」备份一份。
换手机怎么把数据带过去？›
旧手机：「数据导入导出」→ 导出备份文件 → 发给自己的微信文件传输助手。 新手机：下载该文件 → 「数据导入导出」→ 从聊天记录导入。
删掉的记录还能找回吗？›
能，30 天内都可以。删除只是移入「回收站」，到设置 → 回收站里点恢复即可。 超过 30 天会被自动清理，之后无法恢复。
油耗与里程
为什么油耗显示「--」？›
油耗需要「两次加满」才能算出：本次加满，且上一次也是加满（或低油量补油）， 两者之间的里程才算有效区间。只加过一次、或中间有未加满的记录，就会显示「--」。
为什么「总里程」和我仪表盘上的不一样？›
本 App 显示的是建档后行驶里程 = 当前里程 − 购车时填的里程。 这样每公里成本才准确：买车前跑的路不该算进你记录的开销里。
混动车的油耗和电耗怎么分开算？›
加油记录按升算油耗，充电记录按度算电耗，两者分开统计、不会相加。 若填写了 EV / HEV 里程拆分，还能看到各自的占比。
保养提醒
保养提醒什么时候才会亮？›
默认剩余里程 ≤ 500 km 或剩余天数 ≤ 15 天时提醒。 可在车辆详情 → 保养管理里按车调整这两个阈值。
我把保养项全删了，怎么又冒出来了？›
这是旧版本的问题，已修复。现在删光后不会自动重建； 如果想恢复默认的保养项，在保养管理页点「恢复默认」。

① 「推荐给朋友」为什么只有文字能点

现在的实现是用一个 <button> 做透明覆盖层，靠绝对定位铺满整行：

position: absolute; width: 100%; height: 100%; opacity: 0.01;

两个原因导致它没铺满、或者铺满了也点不到：

原因 说明
opacity 接近 0 部分基础库/渲染层会把 opacity: 0.01 的元素判为不可交互，直接跳过命中测试。我之前为绕开 opacity: 0 的问题改成了 0.01，但没解决根因。
button 的默认宽度 <button> 在小程序里有内置的 width/padding/display 规则，width: 100% 未必能完全覆盖。文字能点，说明按钮实际只占了一小块。

修复方案

  • 去掉 opacity，改用 background: transparent + color: transparent —— 元素保持完全不透明，必定参与命中测试，视觉上仍然看不见
  • 用 inset 铺满：left/right/top/bottom: 0 + width/height: auto，比 width: 100% 更能压住 button 的默认尺寸
  • font-size: 0 确保空按钮不被内置行高撑开
  • 显式去掉 ::after 边框（button 默认有一条）

这样改完，可点区域与「关于」「反馈与建议」完全一致，不依赖任何渲染层的宽容度。

② 「我的」改为「设置」

需要同步改 5 处，否则会出现「底栏叫设置、标题栏叫我的」的错位：

位置改后
app.json → tabBar.list[2].text设置
custom-tab-bar/index.ts → TAB_ITEMS[2].text设置
pages/user/index.json → navigationBarTitleText设置
maintain-manage / records / vehicle-form 的删除确认文案「设置 → 回收站」

底栏图标仍用 user 那个，不需要换 —— 齿轮图标会让三个 tab 的视觉重量失衡。

③ 「常见问题」放在哪

按你说的放在「反馈与建议」与「关于」之间：

反馈与建议 → 常见问题 → 关于

这个顺序有逻辑：先让用户自己找答案（常见问题），找不到再去反馈。把「反馈」放前面会让用户跳过自助环节。

需要你确认

  • 常见问题页用「点击展开」的折叠式（原型里这样），还是全部平铺直接展示？
    折叠式页面短、便于扫标题；平铺式不用点，但一屏放不下 9 条。
  • 上面 9 条问题里，有没有你觉得不该写的（比如暴露「以前有 bug」那条），或者要补充的？
  • 要不要在常见问题页底部加一句「没找到答案？点这里反馈」，直接跳到反馈？
