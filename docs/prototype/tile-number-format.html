方案 A · 分段阈值推荐

金额 < 10万 用完整千分位（保精度），≥ 10万 转「万」并用 2 位小数。
里程同规则，阈值 10万 km。
▍小数据（常见）
▍中数据（豪车 / 多年）
▍大数据（极值）
好：99,999 以内保持精确值（用户最想看准数）， 超过才压缩；压缩后最多 7 个字符，三档都不溢出。
代价：边界处会有跳变 —— 99,999 显示 ￥99,999， 100,000 突然变 ￥10万。但这是可接受的，因为跨过 10 万本身就是量级变化。

方案 B · 早启用「万」精度损失

≥ 1万 就用万：￥2.85万。所有数字都很短，但小数据失去精确值。
▍小数据（常见）
▍中数据
▍大数据
好：宽度最稳定，任何量级都不溢出。
差：￥28,450 变成 ￥2.85万， 用户看不到准确金额；而记账类应用里「准确」比「简短」重要。 另外 2.85 万 = 28,500，与 28,450 差 50 元，容易被当成记账误差。

方案 C · 不换单位，自动降字号保精度

数字一律完整千分位，过宽时把字号从 11.5px 降到 10.5 / 9.5。
▍小数据（11.5px）
▍中数据（10.5px）
▍大数据（9.5px，几乎到极限）
好：始终显示精确值，不牺牲可读性语义。
差：同屏字号不一致 —— 两辆车一辆 11.5px、一辆 9.5px， 并排看很乱；再大就降不动了（9px 已是下限）， 7 位数仍会溢出。只能当兜底，不能当主方案。

为什么小数据不转「万」
这是记账应用，用户对金额精确度敏感。
￥28,450 一眼就是准确值；￥2.85万 反而要心算 28,500，还可能怀疑是不是少记了 50 元。

真正需要压缩的是 10 万以上——那时用户对「万」这个量级是自然的。
四舍五入的具体做法
12.845万 是 ￥128,450，2 位小数 → 12.85万
12.804万 → 12.8万（去掉尾 0，不留 12.80）
10.001万 → 10万

去尾 0 很重要：￥10.00万 比 ￥10万 啰嗦且更容易溢出。
