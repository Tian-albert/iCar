需要你先决定的副作用

合并只是 UI 层，但「删除 / 改名」会撞上启动时的补建逻辑。

当前 seedPresetCategories 每次启动都会检查：
「停车 / 高速 / 保险 / 洗车」若不存在就补建。
① 删除预设：删掉「洗车」后，下次启动会被重新建出来。
用户会看到「删了又回来」。
② 改名预设：把「高速」改成「过路费」，下次启动会再建一个「高速」。
结果是两个类别并存，旧的支出还挂在被改名的那个上。
要真正做到「操作一致」，需要改成 预设只在首次安装时创建一次（记录一个已初始化的标记）， 之后完全交给用户管理。这会同时影响「导入旧备份」时的补建行为。
